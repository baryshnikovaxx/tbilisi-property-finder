# Tbilisi Property Finder

Автоматический поиск инвестиционных квартир в Тбилиси (Ваке, Вера,
Мтацминда, Багеби) на myhome.ge: скрапинг → проверка на ошибки
цены/локации/дубли → скоринг → уведомление в Telegram. Работает целиком
на бесплатных сервисах.

## Что уже готово (код)

```
scraper/myhome_scraper.py   — обход 4 районов, пагинация, дедуп, координаты
scraper/districts.py        — id районов на сайте (можно добавить свои)
db/schema.sql                — схема таблиц Postgres
db/db.py                     — сохранение в Supabase/Postgres
scoring/score.py             — скоринг + флаги качества данных
bot/notify_telegram.py       — только новые объекты + алерты на снижение цены
webhook/worker.js            — интерактивный бот (кнопки, /top) на Cloudflare Workers
webhook/wrangler.toml        — конфиг для деплоя воркера
.github/workflows/scrape.yml — ежедневный запуск всего пайплайна бесплатно
```

Критерии по умолчанию зашиты под текущий запрос: до $200,000, 2+ спальни,
55–80 м² (с запасом вокруг 60–70), не первый этаж. Меняются флагами
`--price-to`, `--min-area`, `--max-area`, `--min-bedrooms` в
`myhome_scraper.py`, либо константами в начале `scoring/score.py` (цена/м²,
координаты Круглого сада).

## Что нужно сделать тебе (я не могу создавать аккаунты за тебя)

### 1. GitHub — бесплатный хостинг для расписания
1. Зайти на github.com → New repository (можно private).
2. Загрузить в него содержимое этой папки (`git init && git add . && git commit -m "init" && git push`,
   либо просто перетащить файлы через веб-интерфейс GitHub).
3. Ничего запускать вручную не нужно — расписание уже в `.github/workflows/scrape.yml`
   (каждый день в 07:00 по Тбилиси). Проверить можно во вкладке **Actions** →
   там же кнопка "Run workflow" для ручного запуска.

### 2. Supabase — бесплатная база данных
1. supabase.com → New project (бесплатный план хватает с большим запасом).
2. В **SQL Editor** вставить содержимое `db/schema.sql` и нажать Run —
   создаст таблицы `listings` и `price_history`.
3. **Project Settings → Database → Connection string → URI**, режим
   *Session pooler* (он работает из GitHub Actions, обычный direct
   connection часто блокируется). Скопировать строку — это `DATABASE_URL`.

### 3. Telegram-бот
1. В Telegram написать **@BotFather** → `/newbot` → следовать подсказкам →
   получишь `TELEGRAM_BOT_TOKEN`.
2. Написать своему новому боту любое сообщение (иначе он не сможет писать тебе).
3. Узнать свой `chat_id`: написать боту **@userinfobot** — он пришлёт твой id
   (число, может быть отрицательным, если это группа — тоже подходит).

### 4. Добавить секреты в GitHub
Repo → **Settings → Secrets and variables → Actions → New repository secret**,
добавить три:
- `DATABASE_URL`
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

После этого workflow заработает сам по расписанию — ничего больше делать
не нужно.

### 5. Обновить базу под новые фичи (только-новые + алерты на цену)
В **Supabase → SQL Editor** ещё раз вставить и запустить содержимое
`db/schema.sql` — он идемпотентный (`add column if not exists` и
`create table if not exists`), существующие данные не тронет, просто
добавит недостающие колонки/таблицу. Без этого шага `notify_telegram.py`
упадёт с ошибкой "column notified_at does not exist".

После миграции бот при первом прогоне разошлёт разом все текущие активные
объекты (до `--limit`, по умолчанию 8) — это ожидаемо, дальше уже будут
приходить только реально новые плюс алерты о подешевевших.

### 6. Интерактивный бот (кнопки 👍/👎, команда /top) — опционально
Ежедневная рассылка — это одностороннее push-уведомление. Чтобы бот отвечал
на команды и кнопки, нужен отдельный сервис-приёмник вебхуков от Telegram —
бесплатный Cloudflare Workers подходит с большим запасом для личного
использования, без установки чего-либо на компьютер.

1. **cloudflare.com** → завести бесплатный аккаунт.
2. В дашборде: **Workers & Pages → Create → Create Worker** → дать имя
   (например `tbilisi-property-bot`) → Deploy (создастся заготовка).
3. **Edit code** → стереть всё → вставить содержимое `webhook/worker.js` из
   этого репозитория → **Save and deploy**. Скопировать адрес воркера
   (вида `https://tbilisi-property-bot.<имя>.workers.dev`).
4. **Settings → Variables and Secrets → Add** — добавить три секрета
   (тип **Secret**, не Text):
   - `TELEGRAM_BOT_TOKEN` — тот же токен, что и в GitHub Secrets
   - `SUPABASE_URL` — `https://<project-ref>.supabase.co` (без `/rest/v1`)
   - `SUPABASE_SERVICE_KEY` — **Project Settings → API → service_role key**
     в Supabase (не anon key — этот ключ даёт полный доступ к базе, воркер
     использует его только на сервере, наружу не отдаёт)
5. Сказать Telegram, куда слать апдейты — открыть в браузере (подставив
   свой токен и адрес воркера из шага 3):
   ```
   https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://tbilisi-property-bot.<имя>.workers.dev
   ```
   В ответ должно прийти `{"ok":true,"result":true,...}`.
6. Написать боту в Telegram `/start` — должна прийти подсказка по командам.

Дальше в боте доступно: `/top` — топ-5 активных объектов с кнопками
👍 Нравится / 👎 Не интересно / Ещё ⬇️ (пагинация). Объект, помеченный 👎,
больше не появится ни в боте, ни в ежедневной Telegram-рассылке.

## Локальный запуск (для отладки, до Supabase)

```bash
pip install -r requirements.txt
cp .env.example .env    # заполнить вручную
python scraper/myhome_scraper.py --out listings.csv   # без --db -> просто CSV
python scoring/score.py --csv listings.csv
```

## Дальнейшие шаги (не реализовано, но заложено в архитектуру)

- **Пагинация за пределами первых ~5 страниц на район** — сайт отдаёт
  их стабильно постранично (`&page=N`), просто увеличь `--max-pages`.
- **Telegram-каналы/чаты** как источник — отдельный скрапер на Telethon,
  тот же формат строки в таблицу `listings` (source='telegram').
- **AI-анализ фото и текста** (Claude API) — самое естественное место
  добавить: после `myhome_scraper.py`, перед сохранением в БД — прогнать
  `comment` и ссылки на фото через Claude, получить структурированные
  теги (качество ремонта, вид из окна, доп. риски) и добавить их в
  `listings` новыми колонками.
- **Реальная ликвидность** — `price_history` уже собирает историю цен;
  когда накопится 2–3 месяца данных, можно считать среднее время на
  рынке по району и снижение цены как метрику торга.
- **Мтацминда/Багеби** — их id уже в `districts.py`; если добавишь другие
  районы, ищи их urban_id/district_id так же, как описано в комментарии
  в файле.
- **Реакции 👍/👎 как обучающий сигнал** — сейчас 👎 просто исключает объект
  из показа. Можно пойти дальше: анализировать, что общего у "лайкнутых"
  (район, этаж, цена/м²) и слегка поднимать за это score — уже ближе к
  "система учится вкусу" из первоначальной задумки.
- **Свои веса скоринга через бота** — команда вида `/вес цена -5` в
  `webhook/worker.js`, которая правит константы, влияющие на score
  (сейчас это делается вручную в `scoring/score.py`).

## Известные ограничения прототипа

- URL-фильтры сайта на площадь ненадёжны при прямой навигации — поэтому
  фильтрация по площади/спальням/этажу происходит локально в скрипте,
  не в запросе к сайту.
- Проверка "текст описания не соответствует району" — сейчас это простой
  список ключевых слов (`digomi`, `tabakhmela` и т.д.). Реальная проверка
  через NLP/LLM даст намного больше находок — это первый кандидат на
  подключение Claude API.
- Проверка координат — грубая (расстояние от центра Тбилиси). Точную
  сверку "адрес соответствует координатам" даст только внешний геокодер
  (Google/Yandex Geocoding API — платно, но недорого при таких объёмах).
